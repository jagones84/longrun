# Longrun dependencies.
#
# The harness CORE is stdlib-only + PyYAML. Everything below is either required
# (PyYAML) or OPTIONAL — it unlocks extra capabilities. Install what you need:
#
#     pip install -r requirements.txt
#
# SYSTEM prerequisites are NOT here, and cannot be: pip installs Python packages
# only. The optional external runtimes are:
#   * Node.js (>= 20) — provides `npx`, needed by the stdio MCP servers whose
#     `command` is `npx` (README §MCP servers). A per-user install lands in
#     `~/.local/bin`, which Longrun adds to the launcher PATH itself
#     (`osutil.launcher_path`), so it works even under a systemd user service.
#   * `uv`/`uvx` (Python MCP servers), `docker` (containerised servers).
#   * `pdftotext` (+ `pdftoppm`/`tesseract`), `libreoffice` — document extraction
#     fallbacks when docling/markitdown are absent.

PyYAML>=6.0

# --- Document ingestion for the knowledge base (JAG-403j / JAG-430) -----------
# Two OPTIONAL layers, in preference order. Without either, the harness still
# extracts PDFs via system `pdftotext` (+ `pdftoppm`/`tesseract` OCR for scans)
# and Office files via `libreoffice --headless --convert-to txt`, when those
# binaries exist on the host.
#
# 1. docling (IBM, MIT) — the richest backend: layout-aware reading order and
#    real TABLE structure (TableFormer), plus native images/audio. Pure-Python
#    package (`pip install docling`), Python 3.10+; it pulls torch + a few HF
#    model weights that download once on first use. This is the "optimal RAG
#    ingestion" path (JAG-430).
docling>=2.138

# 2. markitdown (Microsoft, MIT) — a light alternative when docling is not
#    installed: PDF/DOCX/PPTX/XLSX/HTML → Markdown, no torch.
markitdown[pdf,docx,pptx,xlsx]>=0.0.1
